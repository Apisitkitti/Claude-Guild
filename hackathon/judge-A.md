# Judge A — กรรมการสายผลิตภัณฑ์

**มุมมอง:** นักพัฒนาที่เปิด Claude Code หลาย session พร้อมกันแล้วเปิดกิลด์ทิ้งไว้ ฟีเจอร์นี้เปลี่ยนวิธีทำงานหรือความรู้สึกในแต่ละวันไหม หมดความแปลกใหม่ไปแล้วยังจะใช้ต่อไหม

**สูตร:** Total = 2×Impact + Delight + Feasibility + Theme + Risk (เต็ม 60, Risk 10 = เสี่ยงต่ำ)

## สิ่งที่ตรวจกับโค้ด

- `engine.ts:201` ดึง `file_path || path || notebook_path` อยู่แล้วจริง (ทีม 1 และ 4 อ้างถูก)
- `PROGRESS_KEY` ที่ `engine.ts:145`, โหลดและบันทึกที่ `:349` / `:372` เป็น localStorage จริง (ทีม 2 อ้างถูก)
- `MAX_EVENTS = 200` ใน `store.ts:32` จริง (ทีม 3 อ้างถูก)
- hook ทุกตัวใน `hooks/settings.example.json` เป็น `"async": true` + `|| true` แปลว่าส่งผลกลับไปหา Claude ไม่ได้ ทีม 1 จึงเตือนได้แค่ "หลังเกิดเหตุ" ส่วนทีม 4 ต้องมี hook แบบ sync ตัวใหม่ (ทีมระบุไว้แล้ว แต่ต้นทุน latency สูงกว่าที่ pitch บอก)
- engine เรียก `Math.random()` หลายจุด (`:192, :325, :638, :939, :1208, :1210, :1228` …) และผูกกับ `Date.now()` / `performance.now()` ข้ออ้างของทีม 3 ที่ว่า "replay ด้วย engine เดิมได้ ไม่ต้องเขียน logic ใหม่" จึงมองโลกในแง่ดีเกินไป
- ตอนนี้ monster ยังสุ่มจาก `MONSTER_KINDS` ไม่ได้ผูกกับ tool ตาราง tool→มอนสเตอร์ของทีม 2 จึงต้องสร้างใหม่ (ไม่ผิด แต่ไม่ใช่ของที่ "มีอยู่แล้ว")

## คอมเมนต์รายทีม

### ทีม 1 — Territory Clash (49)
- **จุดแข็ง:** ตอบโจทย์คนเปิดหลาย session บน repo เดียวกันโดยตรง เป็นข้อมูลที่ dashboard นี้รู้แต่คนเดียว (มองเห็นทุก session พร้อมกัน) ใช้ path ที่ engine มีอยู่แล้ว ต่อยอดระบบแท็บ / Notification ของ permission alert ได้ทันที เป็นฟีเจอร์เดียวที่ยังมีค่าวันที่ 30 เพราะมันเตือนเฉพาะตอนเกิดปัญหาจริง
- **จุดอ่อน:** hook เป็น async จึงเตือนได้อย่างเดียว กันไม่ได้ และ Edit ของ Claude Code เองก็ปฏิเสธการแก้ไฟล์ที่เปลี่ยนไปหลังอ่านอยู่แล้ว คำว่า "เขียนทับเงียบ ๆ" จึงเกินจริงไปหน่อย ของที่ได้จริงคือเห็นการชนเชิงความหมายและเลิกเสียรอบ retry ส่วน engine ฝั่ง browser ใช้ realpath ไม่ได้
- **ข้อเสนอ:** แยกความรุนแรงเป็นสองระดับ "แตะไฟล์เดียวกัน" (สีเหลือง) กับ "edit ล้มเพราะอีก session" (สีแดง จาก PostToolUseFailure) จะได้ไม่เตือนพร่ำเพรื่อจนคนปิดทิ้ง

### ทีม 2 — Guild Almanac (42)
- **จุดแข็ง:** แก้ปัญหา "วันที่ 5 เหมือนวันที่ 1" ได้ตรงจุด ต่อจาก persistence ที่มีอยู่ logic แยกเป็น pure module ทดสอบง่าย ความเสี่ยงต่ำ
- **จุดอ่อน:** ไม่ได้เปลี่ยนวิธีทำงานของ dev เลย เป็นแค่ retention แบบ gamification Quest แบบ "ล่า Goblin 20 ตัว" คือการให้รางวัลกับจำนวน tool call ซึ่งขัดกับหลัก "ไม่ล่อให้ทำเกินจริง" ที่ทีมเขียนไว้เอง ข้อมูลอยู่ใน browser เครื่องเดียว
- **ข้อเสนอ:** ให้ Quest ผูกกับผลลัพธ์ที่ dev อยากได้จริง เช่น "จบ session โดยไม่มี failure", "ตอบ permission ภายใน 1 นาที", "ไม่โดน compact" แทนการนับปริมาณ

### ทีม 3 — Quest Chronicle (35)
- **จุดแข็ง:** demo moment ว้าวที่สุด การ์ดแชร์ได้ช่วยให้โปรเจกต์ถูกพูดถึง คิดเรื่อง privacy ไว้ดี (ซ่อนชื่อโปรเจกต์, basename)
- **จุดอ่อน:** คุณค่าต่อ dev รายวันต่ำ น่าจะใช้ไม่กี่ครั้งแล้วเลิก timelapse ต้องทำให้ engine deterministic ซึ่งเป็นงาน refactor ใหญ่ (ใช้ Math.random และเวลาจริงทั่วไฟล์) ไม่ใช่ "ป้อน log เข้า engine ตัวที่สอง" แบบที่ pitch บอก log ก็เก็บเฉพาะตอนเปิดแท็บไว้ ข้อมูลจึงขาดเป็นช่วง ๆ สำหรับหนึ่งรอบงานถือว่าเยอะไป
- **ข้อเสนอ:** ตัด timelapse ออกจาก MVP ทำแค่ recap card + Save PNG และเก็บ log ฝั่ง server (ไฟล์ append-only) จะได้ไม่ต้องพึ่งแท็บที่เปิดค้างไว้

### ทีม 4 — Guild Rules / Wards (37)
- **จุดแข็ง:** เป็นทีมเดียวที่เปลี่ยนจาก "ดู" เป็น "คุม" ปัญหามีจริง (.env, force push) คิดเรื่อง fail-open และ opt-in มาดี demo ตอนที่ Claude เปลี่ยนแผนกลางเวทีน่าจะทรงพลัง
- **จุดอ่อน:** ซ้ำกับของที่ Claude Code มีอยู่แล้ว คือ `permissions.deny` และ PreToolUse ที่คืน decision `deny` / `ask` ได้เอง คุณค่าที่เหลือจึงเป็นแค่ UI สำหรับเขียนกฎ ต้องเพิ่ม hook แบบ sync ที่เรียก server ใน tool call ทุกครั้ง ทำให้ dashboard ของเล่นกลายเป็นตัวที่อยู่บนเส้นทางวิกฤติ และ glob ก็หลบได้ ซึ่งเสี่ยงให้ผู้ใช้รู้สึกปลอดภัยเกินจริง ภาพ "วิ่งไปหาหีบ .env" ก็ยังไม่มีแผนที่ไฟล์ใน engine รองรับ
- **ข้อเสนอ:** เปลี่ยนเป็น "Ward Scribe" คือ UI ที่ generate กฎลง `permissions.deny` ใน settings.json ของ Claude Code โดยตรง แล้วกิลด์แค่ "แสดง" ตอนที่กฎทำงาน (จาก PermissionDenied / PostToolUseFailure) แบบนี้ได้ guardrail จริงโดยไม่ต้องรับ latency และไม่ต้องรับผิดชอบเรื่องความปลอดภัยเอง
