# Judge A รอบ 3 (เข้มข้น) — กรรมการสายผลิตภัณฑ์

**มุมมอง:** dev ที่รัน Claude Code หลาย session แล้วเปิดกิลด์ทิ้งไว้ ฟีเจอร์นี้เปลี่ยนวันทำงานไหม พอหายตื่นเต้นแล้วยังใช้ต่อไหม และแผน **หลัง rebuttal** ยังให้คุณค่าตามที่สัญญาไว้หรือเปล่า

**สูตร:** Base = 2×Impact + Delight + Feasibility + Theme + Risk (ให้คะแนนจากแผนฉบับแก้) · −3 ต่อข้ออ้างที่ผมตรวจแล้วไม่จริงและไม่ได้ติดป้าย · −2 ต่อข้อกล่าวหาที่ไม่ตอบหรือตอบเลี่ยง · +2 ต่อการแก้ที่ **เปลี่ยนคุณค่าของผลิตภัณฑ์** จริง (สูงสุด +4 ถ้าเป็นการแก้ hygiene/bug อย่างเดียวไม่ได้โบนัส) · Final = Base − หัก + บวก

## ทีม 1 — Receipt Ledger (45)
- **ดีที่สุด:** ตอบคำถามจริงตอนกลับมาที่โต๊ะว่า "session นี้ได้งานหรือยัง" และเติมแถว "เสร็จแล้ว รอรีวิว" ของ Bell (`lib/attention.ts:286`) ที่ตอนนี้ไม่บอกอะไรเลย เป็นตัวเลขผลลัพธ์ที่ spam ไม่ได้ จึงยังใช้ได้ในวันที่ 30
- **rebuttal:** ตอบครบ 6/6 ได้ +2 จาก R1-1 (ใบเสร็จที่ปิดแล้วมี TTL 2 ชม. ทำให้ปัญหาข้อ 3 ของตัวเองแก้ได้จริง) และ +2 จาก R1-3 (นับ "ฟื้น" ระดับ runner ไม่งั้นตัวนับหลักจะเป็น 0)
- **แย่ที่สุด:** recorder ตัวใหม่ (R1-6) เขียน raw command ลง `.guild/` ซึ่งไม่อยู่ใน gitignore ทีมแก้ privacy เรื่องหนึ่งแต่เปิดรูใหม่อีกเรื่อง ตัวนับ Task/Todo ยังเป็นสมมติฐาน (ติดป้ายแล้ว) และ ~385 บรรทัดก็ชิดเพดาน 400
- **ถ้าชนะต้องแก้:** (1) recorder ต้อง redact และใส่ `.guild/` ใน `.gitignore` (2) แสดงใบเสร็จ **ในแถว done ของ Bell** อย่าแยกเป็นแผงที่สอง (3) จับ fixture ของ TaskUpdate/git commit จริงก่อนเขียน parser

## ทีม 2 — Cartographer's Atlas (35)
- **ดีที่สุด:** แปลงข้อมูลที่ระบบทิ้งอยู่แล้วให้เป็นงานที่ลงมือทำต่อได้ (เขียนอะไรลง CLAUDE.md) ส่วน baseline เทียบ median + แยก hub-list ใน R2-1 คือการแก้ที่มีความหมายจริง (+2)
- **แย่ที่สุด:** มุม product ดูไม่ใช่ของที่ใช้ทุกวัน ได้ insight อาทิตย์ละครั้งแล้วแผงก็นิ่ง ข้อมูลหายเมื่อรีสตาร์ท ไม่แตะ canvas เลย (ธีมอ่อน) และพอตัด highlight ตัวละครออก (R2-3) ก็ไม่มีอะไรเหลือให้เห็นในกิลด์ ส่วน R2-4/R2-5/R2-6 เป็น hygiene ไม่ได้โบนัส
- **ถ้าชนะต้องแก้:** พิสูจน์ด้วย log จริงว่า top-5 ไม่ใช่ไฟล์ hub ก่อน merge แล้วค่อย persist ตัวนับ

## ทีม 3 — Permission Tax (40)
- **ดีที่สุด:** รวม prompt ที่ซ้ำ ๆ จากหลาย session ไว้ที่เดียวแล้วคัดลอก rule ได้เลย ใช้เวลาไม่กี่นาทีแต่คุ้มทุกวัน ได้ +2 จาก R3-2 (เลิกใช้ gap ดิบที่พองด้วยเวลารัน tool) และ +2 จาก R3-1 (metric ไม่วนกลับมาพิสูจน์ตัวเองแล้ว)
- **แย่ที่สุด:** Claude Code มีปุ่ม "don't ask again" ในตัว prompt อยู่แล้ว คุณค่าที่เหลือจึงเป็นแค่ภาพรวม ฟีเจอร์นี้หมดค่าไปเอง (วาง rule ไม่กี่ข้อแล้วแผงก็ว่าง) ตัวเลข "นาที" ส่วนใหญ่กลายเป็น จำนวนครั้ง × ค่าประมาณ 15 วิ (ติดป้าย "~" แล้ว) วิธีปิด wait ชนิดที่ 2 พึ่ง `tool_use_id` ใน PermissionRequest ซึ่งไม่มีหลักฐานใน repo และ **ไม่ได้ติดป้ายสมมติฐาน** (ผมพิสูจน์ไม่ได้ว่าผิด จึงไม่หัก)
- **ถ้าชนะต้องแก้:** จับ payload PermissionRequest จริงเพื่อยืนยัน `tool_use_id`/`permission_suggestions` และชูจำนวนครั้งเป็นตัวเลขหลัก ไม่ใช่นาที

## ทีม 4 — Sentinel Ledger (43)
- **ดีที่สุด:** R4-1 แก้ไปไกลกว่าฟีเจอร์ตัวเอง โดย redact ใน `addEvent` ก่อน slim/SSE (`lib/store.ts:288,313`) ทำให้ทั้งแอปปลอดภัยขึ้น (+2) ส่วน R4-2 ตัดสินจาก PostToolUse เท่านั้น จึงไม่กล่าวหาคำสั่งที่ถูก deny (+2) แถวเหลือง "แก้โค้ดแต่ยังไม่ test" ที่เตือนครั้งเดียวต่อชุด edit เป็นสัญญาณที่ใช้ได้ทุกวัน และไอคอน 🛡 ทึบก็เข้าธีมนักบวช/ยาม
- **แย่ที่สุด:** แถวแดงแทบไม่ขึ้นเลยในวันปกติ คุณค่าเป็นแบบประกันภัยที่คนจะลืมว่ามีอยู่ กฎ regex 5 ชุดรวม allowlist/ข้อยกเว้นทำให้ใช้ ~390 บรรทัด (ชิดเพดาน) และการเปลี่ยนข้อมูลใน store ต้องเทสหนัก
- **ถ้าชนะต้องแก้:** เอาเฉพาะ `redactSecrets` + กฎ 1, 4, 5 ไปก่อน ส่วนกฎนอกโปรเจกต์ (สมมติฐาน add-dir) ค่อยทำทีหลัง
