## ทีม 1 — Receipt Ledger
1. **R1-1 (ร้ายแรง)** "ตอนกลับมาที่โต๊ะ ดูใบเสร็จ session ที่ Stop แล้ว" — ตัว tracker ผูกกับ `dropSession` แต่ sweep ลบ session ที่เงียบเกิน 10 นาที (`lib/store.ts:38,69`) และ SessionEnd ก็ drop ทันที (`:218-221`) → ใบเสร็จหายพอดีตอนที่ผู้ใช้กลับมาดู ปัญหาข้อ 3 ของตัวเองแก้ไม่ได้ · ต้องการ: ใบเสร็จต้องอยู่รอดหลัง session ถูก drop (TTL แยก เช่น 2 ชม. + cap) พร้อม test "Stop แล้วเงียบ 15 นาที ใบเสร็จยังอยู่"
2. **R1-2 (กลาง)** ตัวนับ Todo พึ่ง `TodoWrite.tool_input.todos[]` — client ในรีโปนี้รู้จัก `TaskCreate`/`TaskUpdate` อยู่แล้ว (`lib/office/engine.ts:479`) แปลว่า Claude Code รุ่นปัจจุบันน่าจะใช้ Task tools แทน TodoWrite → ตัวนับนี้มีโอกาสเป็น 0 ตลอด (ติดป้ายสมมติฐานไว้แล้ว แต่ไม่มีแผนรองรับ) · ต้องการ: รองรับ `TaskUpdate status=completed` หรือตัดตัวนับนี้ออกจาก MVP แล้วยอมรับว่ามีแค่ 3 ตัว
3. **R1-3 (กลาง)** "test แดง→เขียว ด้วย fingerprint เดิม" — ในความจริง agent มักรัน `npx vitest run tests/a.test.ts` ตอนแดง แล้วรัน `npm test` ทั้งชุดตอนเขียว fingerprint ไม่เท่ากัน (`lib/attention.ts:126-127`) → นับไม่ได้ (false negative); และ logic "fail แล้ว fp เดิมผ่าน" ก็คือ logic ล้าง loop ของ Lookout Bell (`lib/attention.ts:226-229`) มาเปลี่ยนชื่อ · ต้องการ: นิยาม "ฟื้น" ระดับ runner (คำสั่งไหนก็ได้ที่ match runner เดียวกันใน cwd เดียวกัน) + test เคสต่างคำสั่ง
4. **R1-4 (กลาง)** "subject commit ตัดที่ 80 ตัว" — Claude Code เขียน commit แบบ `git commit -m "$(cat <<'EOF'` บรรทัดแรกจึงไม่มี subject; ยัง `--amend`, commit ที่ pre-commit hook ทำให้ล้ม/สำเร็จบางส่วน ไม่ได้แยก · ต้องการ: parser ที่รองรับ heredoc + ไม่นับ `--amend` ซ้ำ + fixture จริง
5. **R1-5 (เล็ก)** อ้างอิงผิดบรรทัด: `failed =` อยู่ `lib/attention.ts:210` ไม่ใช่ `:204`; `is_interrupt` `:211` ไม่ใช่ `:205`; `PostToolUseFailure.error` อยู่ `hackathon/round2/RESULTS.md:22` ไม่ใช่ `:19`; `snapshot()` `lib/store.ts:319` · และ "error มาใน PostToolUseFailure" เป็นคำพูดกรรมการ ไม่ใช่ fixture payload · ต้องการ: แก้บรรทัด + แนบ payload จริงหนึ่งตัว
6. **R1-6 (เล็ก)** ตัวชี้วัด "ตรงกับ git log ≥90%" ต้อง replay 10 session แต่ `store.events` เก็บแค่ 200 ตัวและเป็น event ที่ slim แล้ว (`lib/store.ts:36,288`) — todos/command ยาวหายไปแล้ว ใช้ทำ fixture ไม่ได้ · ต้องการ: บันทึก raw ก่อน slim (ไฟล์ทดสอบเท่านั้น) หรือเปลี่ยนวิธีวัด

## ทีม 2 — Cartographer's Atlas
1. **R2-1 (ร้ายแรง)** แกนของฟีเจอร์ "Confusion = reads ≥3 ไม่มี edit / ≥2 session อ่าน" — นี่คือ proxy ของ "ไฟล์สำคัญ" ไม่ใช่ "ไฟล์งง": ทุก session อ่าน `lib/store.ts`, `package.json`, `CLAUDE.md` เพราะเป็นศูนย์กลาง; Read ซ้ำหลัง compact; Edit ล้ม (`old_string` ไม่เจอ) มักเกิดจากอ่านไฟล์เก่า ไม่ใช่ไฟล์อธิบายยาก → false positive เป็นค่าเริ่มต้น และ metric 1 (≥60%) ให้ผู้ใช้ตัดสินเองซึ่งวัดแบบอัตวิสัย · ต้องการ: baseline ที่หักความถี่ปกติ (เช่น reads/session เทียบค่ากลางทั้งโปรเจกต์) + ตัวอย่างจาก log จริงว่า top 5 ไม่ใช่แค่ไฟล์ hub
2. **R2-2 (กลาง)** อ้าง Read/Grep path จาก `lib/office/engine.ts:466,477` และ `lib/office/sim.ts:33` — ทั้งหมดเป็นโค้ด **client/ตัวจำลอง** ไม่ใช่หลักฐาน payload; sim เองส่ง Grep/Glob โดยไม่มี `path` (`lib/office/sim.ts:34-35`) · ต้องการ: payload Grep/Glob/Read จริงหนึ่งตัว และยืนยัน `offset/limit` ก่อนใช้ในตรรกะจัดกลุ่ม
3. **R2-3 (กลาง)** "ไม่แตะ canvas เลย" ขัดกับ demo "คลิกแถว → highlight ตัวละครที่เพิ่งแตะ" — highlight ตัวละครคือการวาดบน canvas เสี่ยงชนกฎห้ามย้อมสี/ห้ามโปร่งใสทับตัวละคร · ต้องการ: ระบุวิธี highlight (เช่น ลูกศรทึบเหนือหัว) และนับบรรทัดใน `lib/office/render.ts`
4. **R2-4 (กลาง)** `fs.readdir` บน `cwd` ที่มาจาก hook payload (`lib/store.ts:11,253`) — server จะ list โฟลเดอร์ใดก็ได้ที่ payload บอก แล้วส่งชื่อไปหน้า UI; ไม่มีเพดานจำนวน entry · ต้องการ: readdir เฉพาะ cwd ที่ session จริงรายงาน + จำกัดจำนวน + test path traversal/โฟลเดอร์ใหญ่
5. **R2-5 (เล็ก)** test ที่ `lib/atlas.test.ts` จะ **ไม่ถูกรัน**: vitest include แค่ `tests/**/*.test.ts` (`vitest.config.mts:10`) · ต้องการ: ย้ายไป `tests/atlas.test.ts`
6. **R2-6 (เล็ก)** หน่วยความจำ: 2000 ไฟล์ × 20 cwd = 40,000 แถว แต่ละแถวมี `sessions:Set` ไม่จำกัด + ไม่ล้างเมื่อ dropSession; "Hot 24 ชม." แต่ข้อมูลหายเมื่อ restart; metric 3 "เปิดแผง ≥3 ครั้ง/วัน" ไม่มีโค้ดนับ · ต้องการ: cap ต่อ Set + global cap + ระบุตัวนับการเปิดแผง; อ้างบรรทัด dedupe ผิด (`lib/attention.ts:214-219` ไม่ใช่ `:207-216`)

## ทีม 3 — Permission Tax
1. **R3-1 (ร้ายแรง)** ตัวชี้วัดหลัก "prompt ที่ตรง rule ที่คัดลอกลดลง ≥50%" เป็น **tautology**: rule ใน `permissions.allow` ทำให้ prompt นั้นไม่เกิดตามนิยาม — วัดได้แค่ว่าผู้ใช้วาง rule หรือไม่ ไม่ได้วัดเวลาที่ได้คืน · ต้องการ: metric ที่ไม่ผูกกับตัวเอง เช่น นาทีรอรวม/วันของทุก prompt ลดลงเท่าไร เทียบสัปดาห์ก่อน
2. **R3-2 (ร้ายแรง)** "นาทีที่รอ" = PermissionRequest → event ถัดไป (`lib/store.ts:245-250`) — หลัง grant event ถัดไปคือ PostToolUse ของ tool นั้น ซึ่งมาหลัง tool **รันจบ**; demo ใช้ `npm test` (รันเป็นนาที) ตัวเลขภาษีจึงพองด้วยเวลารัน test เกือบทั้งหมด; รอบที่ PreToolUse ของ tool ถัดไปมาถึงช้าเพราะ async ก็ปิด wait ผิดได้ (`hooks/settings.example.json:8`) · ต้องการ: ปิด wait ที่ PreToolUse ของ tool_use ถัดไป/ข้อความ UserPromptSubmit แทน หรือหักค่าเวลารันโดยประมาณ (ใช้ `PERM_STALE_MS` เป็นตัวอย่างการยอมรับว่าไม่มี grant hook `lib/attention.ts:25-26`)
3. **R3-3 (กลาง) ความเป็นส่วนตัว** "เก็บแค่ fingerprint+label" แต่ label = `target` 80 ตัวแรกของคำสั่ง (`lib/attention.ts:127`) ซึ่งมี token ได้ (`curl -H "Authorization: Bearer …"`) แล้วเขียนลง `.guild/` ซึ่ง **ไม่อยู่ใน `.gitignore`** (`.gitignore` ทั้งไฟล์ไม่มี `.guild`) และมีไฟล์ `token` อยู่แล้ว · ต้องการ: mask secret ก่อน persist + ใส่ `.guild/` ใน `.gitignore` + test
4. **R3-4 (กลาง)** "Copy rule จาก fingerprint" — `fp` เป็น hash fnv (`lib/attention.ts:127`) สร้าง prefix rule ไม่ได้; ต้องเก็บคำสั่งเต็ม (ขัดกับข้อ R3-3) หรือพึ่ง label ที่ถูกตัด; ไม่ใช้ `permission_suggestions` ที่ Claude Code แนบมากับ PermissionRequest (สมมติฐานของ red team — ต้องเช็ค payload) · ต้องการ: อธิบายการสร้าง prefix จากคำสั่ง + test `cd x && npm test`, `FOO=1 npm test`
5. **R3-5 (กลาง)** ซ้อนกับ Lookout Bell: แถว permission + `waitingSince` มีอยู่แล้ว (`lib/attention.ts:264-268`, `lib/store.ts:246`) และข้าม subagent ทั้งหมด (`lib/store.ts:243`) ทั้งที่ prompt ของ subagent ก็ทำให้ผู้ใช้รอ → ตัวเลขต่ำกว่าจริงเชิงระบบ · ต้องการ: นับ subagent แยกป้าย หรือบอกชัดใน UI
6. **R3-6 (เล็ก)** ตัวนับ "rule ถูกคัดลอก" ฝั่ง server ต้องมี endpoint ใหม่ ไม่อยู่ในรายการไฟล์ MVP · ต้องการ: ระบุ route + นับบรรทัด

## ทีม 4 — Sentinel Ledger
1. **R4-1 (ร้ายแรง) ความเป็นส่วนตัว** "mask secret ก่อนเข้า snapshot" เป็นละคร: `evt` ที่ slim แล้วยังเก็บ `command`/`content` 300 ตัวแรก (`lib/store.ts:273,288`) ลง `store.events` และ **broadcast ทาง SSE ทุก event** (`lib/store.ts:313`) + snapshot (`:322`) → `sk-…`/`AKIA…` ไปถึง UI อยู่แล้ว ฟีเจอร์ที่ "ตรวจ secret" แต่ปล่อย secret ตัวเดิมผ่านท่อข้าง ๆ · ต้องการ: redact ใน `addEvent` ก่อน slim/broadcast + test ว่า SSE payload ไม่มีค่าจริง
2. **R4-2 (ร้ายแรง)** "เกิดไปแล้ว" — ไม่ระบุว่า classify จาก PreToolUse หรือ PostToolUse; PreToolUse ยิงก่อนการขออนุญาต ถ้าผู้ใช้ **deny** `git push --force` UI จะกล่าวหาว่าเกิดแล้ว · ต้องการ: กฎ 1-4 ใช้ PostToolUse สำเร็จเท่านั้น (secret ใน input ใช้ Pre ได้แต่เขียนว่า "พยายาม") + test เคส deny
