# Team 4 "นักบวช" — Infirmary: โรงพยาบาลสนามของกิลด์ (ตรวจอาการ session ที่ป่วย + เตือนคนที่หมดแรง)

**One-liner:** server ดู hook stream แล้วจับอาการ "วน loop / พังซ้ำ / context จะเต็ม / รอคุณนานเกิน / คำสั่งเสี่ยง" ของแต่ละ session — นักบวช NPC เดินไปร่ายฟื้นฟูที่ตัวนั้นพร้อมใบวินิจฉัยที่ copy ไปแปะเตือน Claude ได้ และเตือนตัวคุณเองเมื่อนั่งนานเกิน

## ปัญหา
รัน 4-5 session พร้อมกัน มองไม่ทันว่าตัวไหน "ยุ่งอยู่" กับ "ติดหล่ม": Claude รัน `npm test` พังท่าเดิม 6 รอบ, แก้ไฟล์เดิมวนไปมา, ตัวหนึ่งรอ permission มา 20 นาทีโดยไม่มีใครเห็น, context 92% แล้วคุณภาพตก — เปลืองเงิน/เวลาเงียบ ๆ และคนก็นั่งเฝ้าจอยาวไม่ได้พัก Round 1 Wards (ห้ามเข้าเขต) ถูกติเพราะ hook async ขวางไม่ได้ → รอบนี้เปลี่ยนเป็น "ตรวจจับและเตือน" ซึ่งทำได้จริง 100%

## ทำงานยังไง
**Data source (มีอยู่ใน store แล้ว ไม่ต้องเพิ่ม hook):**
- `PreToolUse`: `tool_name`, `tool_input.command/file_path/pattern` → ทำ fingerprint `tool+input ย่อ` (store slim เหลือ 300 ตัวอักษรอยู่แล้ว)
- `PostToolUseFailure`: `tool_name`, `error` (string), `is_interrupt` — ผูกกับ fingerprint เดิมด้วย `tool_use_id` (กันนับซ้ำ ตามที่ judge ติดรอบ 1)
- `PostToolUse` (นับสำเร็จ รีเซ็ต streak), `UserPromptSubmit`/`Stop` (ขอบเขต "turn", วัดเวลาทำงานจริง), `Notification`/`PermissionRequest` (มี `s.waiting` อยู่แล้ว → วัดว่ารอนานเท่าไร), `s.context` (% context จาก transcript.ts)
**ตัวตรวจ (ฝั่ง server ใน `lib/health.ts`, เรียกจาก `ingest` ใน store.ts เหมือน TerritoryTracker; ฟังก์ชันบริสุทธิ์ ไม่ผูก React):**
1. 🔁 **Loop**: fingerprint เดิม fail ≥3 ติด หรือ Edit ไฟล์เดิม ≥6 ครั้งใน turn เดียวโดยไม่มี Bash test สำเร็จคั่น
2. 🩸 **Failure streak**: fail ≥4 จาก 5 tool call ล่าสุด (ไม่นับ `is_interrupt` ที่คุณกดหยุดเอง)
3. 🧠 **Context เหนื่อย**: `context` ≥85% (ค่า %: ถ้าอ่านไม่ได้ก็ข้าม)
4. ⏳ **รอคุณ**: `waiting` เกิน 5 นาที → ไฟกะพริบ + ลำดับ "ใครรอนานสุด" ใน roster
5. ⚠️ **คำสั่งเสี่ยง** (regex ใน Bash `command`): `rm -rf`, `git push --force`, `git reset --hard`, `DROP TABLE`, `curl … | sh`, `chmod -R 777` → ขึ้นป้ายเตือน *หลังเกิดเหตุ* ไม่ใช่ห้าม
6. 🫖 **สุขภาพคน**: นับเวลา "มี session ทำงานต่อเนื่อง" (ช่องว่างไม่เกิน 10 นาที) → 90 นาทีขึ้นป้ายชวนพักที่โรงเตี๊ยม, 3 ชม. ขึ้นแรงขึ้น; ปิด/ตั้งเวลาเองได้ (opt-in ใน localStorage)
**สิ่งที่แสดง:** แต่ละ session มีแถบ HP (หัก ตามอาการ) ใน roster + ไอคอนอาการเหนือหัว; นักบวช NPC เดินไปยืนข้างตัวที่ป่วยแล้วเล่นท่าร่าย (เอฟเฟกต์วาดข้างตัว ไม่ทับ ไม่โปร่งใส ตามกฎ canvas); คลิกตัว → ใบวินิจฉัยภาษาไทยสั้น ๆ เช่น "`npm test` พังซ้ำ 5 ครั้ง ข้อความเดิม: Cannot find module 'x'" + ปุ่ม **Copy คำเตือน** (ข้อความให้คุณแปะใส่ session: "หยุด ลองแนวทางอื่น ก่อนรันซ้ำอธิบายว่าต่างจากเดิมยังไง")
**Demo moment:** ยิง curl จำลอง `PostToolUseFailure` เดิม 3 ครั้ง → HP ของ Rogue ร่วงเป็นสีแดง ไอคอน 🔁 โผล่ นักบวชวิ่งมาร่ายเวท ใบวินิจฉัยเด้ง กดคัดลอกแล้วแปะ — และกรรมการเห็น `?demo` มี scenario "ติดหล่ม" เล่นเองได้

## ทำไมคุ้ม
- ประหยัดของจริง: จับ loop ได้ตั้งแต่ครั้งที่ 3 แทนปล่อยไป 20 ครั้ง (ทั้ง token และเวลา); ผู้ใช้หลาย session ได้ "คิวสิ่งที่ต้องดู" ที่เรียงตามความเร่งด่วน — ตอบโจทย์ dashboard ที่ผ่านมาที่แค่ "ดู"
- ไม่ต้องตั้งค่าอะไรเพิ่ม ใช้ hook ที่ติดตั้งอยู่แล้ว ไม่เสี่ยง latency และตรงตามข้อแก้ judge: ตรวจฝั่ง server, แยกระดับความร้ายแรง (ข้อมูล/ควรดู/อันตราย), ไม่โฆษณาเกินจริง

## ขอบเขต MVP (ประมาณ M, 1 รอบงาน)
- ใหม่: `lib/health.ts` (ตัวตรวจ 1-4 + 6, ฟังก์ชันบริสุทธิ์ + vitest ด้วย event ปลอม); ปลอดภัย ไม่มี I/O
- แก้: `lib/store.ts` (เก็บ `health` ต่อ session, broadcast ผ่าน SSE แบบเดียวกับ context, bump STORE_VERSION), `lib/office/engine.ts` + `render.ts` (ไอคอน/HP bar/นักบวช NPC เดินไปรักษา), `components/OfficeApp.tsx` (HP ใน roster, ใบวินิจฉัย, ปุ่ม copy, ป้ายชวนพัก)
- ถ้าเวลาเหลือ: ข้อ 5 (risky command) และ scenario ใน demo sim; ตัดออกก่อน: การตั้งค่าเกณฑ์เอง

## ความเสี่ยง + วิธีกัน
- **เตือนพร่ำเพรื่อ (false positive):** เกณฑ์อนุรักษ์ + cooldown 5 นาทีต่ออาการ + dismiss ได้ + fail ที่ `tool_use_id` เดียวกันนับครั้งเดียว; Bash ที่ error ต่างกันเรื่อย ๆ (กำลัง debug จริง) ไม่นับว่า loop เพราะเทียบ fingerprint ของ error ด้วย
- **ข้อจำกัดของ hook:** async → ขวางไม่ได้, เตือนได้หลังเกิด; เราไม่ inject ข้อความเข้า session (ไม่มี API) จึงเป็น "ใบแนะนำให้คนไปแปะ" เท่านั้น; ไม่มี hook "คนกด approve" ดังนั้น `waiting` อาจค้างเกินจริง (ตามที่ README ระบุ)
- **Privacy:** ใช้เฉพาะ fingerprint + error 300 ตัวแรกที่ store เก็บอยู่แล้ว ไม่เก็บ prompt/tool_response; ทุกอย่างอยู่ใน memory เครื่องเดียว; ไม่ log คำสั่งเสี่ยงลงไฟล์
- **สุขภาพคน = ไม่ใช่การแพทย์:** ข้อความเป็นแค่ชวนพักแบบเป็นกันเอง ไม่วินิจฉัย; ปิดได้ทั้งหมด
- **Canvas:** HP/ไอคอนวาดทึบข้างตัวละคร ไม่ทับ sprite; ข้อความไทยวาดด้วย font เดียวกับ roster เพื่ออ่านชัด
