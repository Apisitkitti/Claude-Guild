## เช็กความเป็นไปได้กับโค้ด (สั้น ๆ)

- engine ใช้ `Math.random()`/`Date.now()` กระจายหลายจุด และ `store.ts` เก็บแค่ `MAX_EVENTS = 200` → replay แบบ deterministic ของ Team 3 ต้อง refactor มากกว่าที่ pitch บอก

## ความเห็นรายทีม

### Team 1 — Territory Clash (48)
- **จุดแข็ง:** event เกมที่ซื่อตรงที่สุดในทุก pitch — "ดาบไขว้" เกิดเพราะสอง session แตะไฟล์เดียวกันจริง ๆ ไม่ใช่ตัวเลขสุ่ม; ใช้ข้อมูลที่มีอยู่, reuse alert/notification เดิม, demo moment เข้าใจทันที
- **จุดอ่อน:** เป็นเหตุการณ์ที่เกิด "นาน ๆ ครั้ง" — ช่วยกันงานพังได้ แต่แก้ปัญหา "กิลด์น่าเบื่อ" ในชีวิตประจำวันได้น้อย; คนที่ใช้ session เดียวจะไม่เคยเห็นเลย; เสียง clang ยังไม่มีระบบรองรับ
- **ข้อเสนอดีไซน์:** ทำ "ดินแดน" ให้มองเห็นได้ตลอดเวลา ไม่ใช่แค่ตอนชน — เช่นธงเล็กสีประจำตัวปักบนไฟล์/โซนที่แต่ละคนกำลังถือครอง ให้ฉากมีชีวิตขึ้นทุกวัน แล้ว Clash เป็นจุดพีคของระบบนั้น

### Team 2 — Guild Almanac (49) — ผู้ชนะของกรรมการ C
- **จุดแข็ง:** ตอบโจทย์ "น่าเบื่อ" ตรงที่สุด — เพิ่มวงจรเกมระยะยาว (สะสม, เควสรายวัน, ตรา) ที่ทำให้มีเหตุผลกลับมาดู; Bestiary ผูกมอนสเตอร์กับ tool จริงทำให้โลกมี "ความหมาย" มากขึ้น; ระวังเรื่องเควสที่ล่อให้ใช้ tool เปลือง ซึ่งเป็นความเข้าใจเกมดีไซน์ที่ดี
- **จุดอ่อน:** เควสบางแบบ ("ล่า Goblin 20 ตัว") ยังเสี่ยงเป็น grind ที่ไม่มีความหมาย; หลายฟีเจอร์ (Bestiary + Quest + Chronicle) อาจล้นรอบเดียว; ต้องเปลี่ยน mapping มอนสเตอร์ใน engine ซึ่ง pitch ประเมินต่ำไป
- **ข้อเสนอดีไซน์:** ให้เควสวัด "ผลลัพธ์ที่ดี" ไม่ใช่ปริมาณ — เช่น "ปิดเควสโดยไม่เสียหัวใจ", "บอสตายภายใน 60s", "จบ session ก่อนมานาเกิน 80%" และให้ discovery ของ Bestiary มีโมเมนต์บนแคนวาสจริง (มอนตัวใหม่เรืองแสง/ป้าย NEW เหนือหัว) ไม่ใช่แค่ toast

### Team 3 — Quest Chronicle (37)
- **จุดแข็ง:** demo moment สวยและ "แชร์ได้" — การ์ดตำนาน + timelapse เป็นเรื่องเล่าที่ดี; ตำแหน่งอย่าง "Bash Berserker" มาจากข้อมูลจริง
- **จุดอ่อน:** เป็นของ "หลังเลิกเล่น" ไม่ได้ทำให้กิลด์สดขึ้นตอนดู; replay ต้องการ engine ที่ deterministic ซึ่งตอนนี้ไม่ใช่ (Math.random/Date.now หลายจุด) + log ต้องเก็บใหม่ทั้งหมด → ความเสี่ยงเลื่อนหลุดรอบสูง
- **ข้อเสนอดีไซน์:** ตัด timelapse ออกจาก MVP แล้วทำ "Recap card" ให้สุดก่อน — หรือเปลี่ยนเป็น "highlight reel" ที่บันทึกแค่ 5 โมเมนต์ใหญ่ (boss kill, level up, quest complete) แทนการ replay ทั้งวัน

### Team 4 — Guild Rules / Wards (38)
- **จุดแข็ง:** แฟนตาซีแรงที่สุด — กิลด์เปลี่ยนจาก "ผู้ชม" เป็น "ผู้พิทักษ์" และ Claude ตอบสนองต่อโล่สด ๆ เป็น demo ที่ wow มาก; เป็น event ที่เกิดจากการกระทำจริง 100%
- **จุดอ่อน:** ต้องเปลี่ยน hook จาก async ไม่ขวางงาน เป็น synchronous ที่ปฏิเสธ tool ได้ — เพิ่ม latency ทุก tool call และถ้ามีบั๊กคือบล็อกงานผู้ใช้จริง; ทับซ้อนกับ permission/deny ของ Claude Code ที่มีอยู่แล้ว; ขอบเขตงาน (hook ใหม่ + route + matcher + UI + แอนิเมชัน) ใหญ่กว่า M
- **ข้อเสนอดีไซน์:** รอบแรกทำเป็น "Watchtower" — โหมดสังเกตอย่างเดียว (ใช้ hook async เดิม) ที่ให้ยามบนหอคอยตะโกน/ยิงพลุเมื่อมีการแตะ `.env` หรือ `push --force` แล้วค่อยต่อยอดเป็น Ward ที่ deny จริงเมื่อพิสูจน์ความเสถียรแล้ว
